# 从过往对话里挖开发技巧

- 目标：不凭空总结，从真实开发对话里找出值得放进 harness 的技巧。
- 范围：2026-08 到 2026-10 的云端会话，重点看 X Pro 推送脚本、CEO agent 任务聚合、Claude Remote 保活脚本、AI 与人的协作方式、视频剪辑（HyperFrames）、fewunderstand 分支清理。只读了用户消息，长会话没有逐条读完。
- 结论（对应 `skills/dev-techniques`）：

| 技巧 | 来源（大意） |
|---|---|
| 先搜开源 | CEO agent：「你帮我上网找找有没有人已经做好，这很重要，我担心做得太重或没别人好」；HyperFrames 直接用开源框架 |
| 先看平台自己有没有 | X Pro：用平台自带的推送拿数据，而不是写爬虫；「管理页面要不要做，还是直接看推特自带的列表」 |
| 先讲方案再动手 | X Pro：「我们要不要先讨论方案？你告诉我准备做成什么样，我看了再去做」 |
| 复用已有环境和登录态 | X Pro：多次纠正「用我现有的 Edge 窗口，已经登录好了」，Agent 反复要开专用窗口 |
| 测试数据用完就清 | X Pro：「用测试列表去研究，研究完删掉，然后按方案做」 |
| 不悄悄降级 | 视频剪辑：「你会默认改我的分辨率吗？用原版分辨率不可以吗」 |
| 真实环境端到端 | X Pro：「用真实账号跑一遍端到端验证」 |
| 交付要看得懂、第一句说成没成 | 「啥意思，成功了吗？」；AI 协作：「一下子做十几个模块，我要去理解每个模块，学不动」「让 AI 不懂的地方问我，我专注细节可以，统筹会卡住」 |
| 能先跑就先跑 | CEO agent：「流程主要卡在我审批和理解，应该 AI 先跑起来，我负责修改」 |
| 独立模块 + 接口 | X Pro：「这边代码能实现就行，部署时让那边的 Agent 来读这个库」；CEO agent：「做接口提交比较方便，不然它还要读那边的文档」 |
| 交接提示词 | fewunderstand：「你给我一段提示词，我问问 Hermes 那边做了没有」 |

- 没收的：中文回复、用哪个框架、部署在哪台机器，这些属于习惯或选型。
